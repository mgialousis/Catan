# Protocol and architecture decisions — Phases 1–2

Approved scope: Phase 1 foundation and Phase 2 private lobbies. Protocol **1**, stored-state schema **1**, rules **base-2020-v1**. Working name **Island Table**. Approved timer, pause, identity-loss, capacity and retention defaults remain as described in PLAN.md.

## Wire source of truth

`packages/protocol/schemas/v1.json` is a JSON Schema draft-07 document. `events.json` maps Socket.IO events to definitions. TypeScript uses Ajv; Flutter uses `json_schema` against a byte-identical bundled copy generated by `npm run protocol:sync`. Manually authored TypeScript contracts describe internal programming interfaces. Shared positive/negative fixtures verify the actual wire format across languages; no claim of automatic cross-language type generation is made.

Every command in PLAN.md has a discriminated payload schema. Unknown fields, forged actor fields, unsupported versions, negative/fractional/excessive resource quantities and malformed IDs are rejected. Rule legality, valid board topology, and relationships such as `toVersion = fromVersion + 1` are separate semantic checks introduced when their handlers/reducers are implemented.

One clarification from the illustrative blueprint: activity items now use the explicit `{type, actorPlayerId, message}` schema. Event messages must be generated from allowlisted public facts. They must never contain private resource types or arbitrary submitted strings. The blueprint's illustrative `edgeId` activity property is represented in the public message for v1.

`NOT_IMPLEMENTED` and `INVALID_PAYLOAD` are added error codes. Phase 1 command endpoints reject all valid future mutations with `NOT_IMPLEMENTED`; they do not create receipts or pretend to commit a move. Malformed packets receive `session.error`. Phase 2 replaces room stubs with authenticated membership checks; game reads remain unavailable.

`auth.refresh` has a small transport acknowledgement: `{status:"ACCEPTED",serverTime}`. A failed refresh emits a sanitized session error and disconnects. It is not a durable gameplay command. Flutter currently reconnects on SDK token refresh so all authorization runs again; the endpoint is covered by the gateway tests.

## Privacy and state

Pure contracts live in `@island/protocol/contracts`; importing them from the engine performs no filesystem, socket, database or environment access. The schema validator's Node filesystem loader lives in the separate package entry point.

`CanonicalState` separates `publicState`, a player-keyed private map, server-only bank/deck/setup/effect state, and durable clocks. Public types include the board graph, buildings/roads, public counters, trades, phase/continuation context, awards and deadlines. `projectPlayer` explicitly copies only the selected owner's fields. Phase 3 adds recursive public/owner projections and typed effect filtering. Authorized delta generation and immutable client delta reduction remain Phase 4–5 work; the running gateway still emits lobby data only.

Patch roots are allowlisted, but a patch's `value` is intentionally generic JSON. The wire schema rejects prototype-related path segments. Future reducers must also reject dangerous path segments, apply public/private patches atomically, then validate the resulting complete projections. Never treat patch-schema validation alone as proof of privacy or game legality. Completed-game result disclosure requires an additive schema revision before its later implementation.

## Board identifiers and state-machine contracts

Topology version 1 uses 19 axial hex coordinates with radius 2. Integer vertex coordinates use centers `(2q+r,3r)` and corner offsets `(0,2),(1,1),(1,-1),(0,-2),(-1,-1),(-1,1)`. Assign hex IDs `h-N`, vertex IDs `v-N`, and edge IDs `e-N` after a fixed numeric lexicographic sort; edges use sorted endpoint pairs. Persist generated topology and layout so screen coordinates never become authoritative identifiers. Phase 3 generates and verifies the 19/54/72 graph, nine coastal ports and bounded random layouts.

The durable transition graph includes pre-roll development effects returning to `AWAIT_ROLL`. `PRODUCTION` and `END_TURN` are atomic transient operations, never stored phases. `COMPLETE` has no gameplay exit. The transition adjacency list is a contract, not a rules validator. Timers, actor checks, continuations and own-turn victory checks remain part of the later engine implementation.

## Database ownership and transactions

Migration execution uses Supabase's privileged local `postgres` connection and assigns all application tables/functions to NOLOGIN `island_owner`. Creating foreign keys as the migration executor avoids requiring the owner role to access Supabase's managed `auth` schema. The server connects directly as `island_runtime`, has no owner-role membership, and readiness rejects a connection as any other role.

All eight application tables have RLS. API roles have no `app` schema privileges or policies, and `app` is excluded from PostgREST's exposed schemas. Runtime has only required SELECT/INSERT/UPDATE privileges; move logs are append-only and outbox updates are limited to delivery metadata. Cleanup and receipt tombstone maintenance require the operator role.

Database constraints enforce the active slot, seat/name/colour uniqueness, same-room foreign keys, deferred host creation, final-only receipts and outbox version ordering. Migrations are tracked both by Supabase's runner and application compatibility metadata. Cross-field JSON semantics are validated by the versioned application schemas, not fully duplicated in SQL.

The transaction helper uses one checked-out client, bounded timeouts, rollback and release. Phase 2 implements command advisory locks, room version checks, runtime fencing, and atomic room/receipt/outbox commits with retries. Game state/move-log commits and game-delta delivery remain Phase 5 work.

## Authentication and transport

JWT validation checks signature, allowed algorithm, issuer, audience, expiry, issued-at presence, UUID subject and authenticated role. Production uses ES256/RS256 JWKS with HTTPS; legacy HS256 is an explicitly configured local-only fallback, rejected in production. Unknown keys and unavailable verifiers fail closed.

Socket.IO uses only WebSocket transport, a 16 KiB inbound limit, 25s/20s heartbeat, an explicit browser origin allowlist, per-IP connection limits and per-user request limits. Native clients may omit Origin but always authenticate. Tokens are transmitted in the handshake auth object, never in query strings. Each supported packet is validated, rate limited and reauthenticated. Expiry disconnects the socket. The shared 128 KiB outbound snapshot target will be enforced and measured when snapshots exist.

No complete payloads, tokens, SQL credentials or private states are logged. The local configuration helper captures Supabase CLI output without printing credentials. Supabase SDK restores persisted identity; failed refresh never silently creates a replacement guest.

## Phase 2 — lobby decisions and review resolutions

Phase 2 implements the room command catalogue except rematches and actual game initialization. The
server enforces start eligibility under the room lock; an eligible `START_GAME` returns the durable
`GAME_NOT_AVAILABLE` rejection and leaves the lobby unchanged. Creating a real match and testing a
join racing that transition require the Phase 3 initializer and Phase 5 integration.

- **Membership:** `session.membership: {roomId, playerId}` is an additive v1 owner-only notification.
  A verified guest is automatically restored to their own ongoing membership. Public snapshots never
  contain Auth IDs, credentials, invitation plaintext or invitation hashes. Every subscription and
  publication checks current membership. A second tab counts as the same seated player.
- **Names:** the JSON schema bounds the wire envelope; the server enforces 2–20 grapheme clusters,
  NFKC normalization, trimming, repeated ordinary-space collapse, and rejects Unicode control,
  format, line-separator and paragraph-separator characters. Lowercase comparison is deliberate,
  not full Unicode case folding: `Straße` and `STRASSE` remain distinct. Flutter provides immediate
  length feedback; the server reports semantic rejection without changing the room.
- **Invitations:** ten uniformly sampled Crockford Base32 symbols (50 random bits); the server
  accepts lowercase, spaces and hyphens but stores only SHA-256 on the room. Host-only receipt
  responses retain plaintext for retries. Rotation invalidates the old code, not existing seats.
  Admission codes expire after 24 hours; idle lobbies expire after 24 hours without a durable user
  change. Host/presence housekeeping does not extend this activity timestamp.
- **Storage:** native lobby context and pending intents use secure storage. Web uses origin-scoped
  preferences, alongside the existing Supabase guest session. A host invitation is intentionally
  persisted to support reload/retry; it grants lobby admission only, never seat ownership. It is
  cleared from UI storage on leaving, switching tables or losing host controls. No game hand or
  private game snapshot is stored. Lost Auth identity does not claim a saved seat by nickname.
- **Links:** Web uses `/?invite=CODE` (hash-query form is accepted too). Installed native apps register
  `islandtable://join?invite=CODE` via pinned `app_links 7.0.0`; Flutter's default native deep-link
  handler is disabled for that plugin. `shared_preferences 2.5.5` and `app_links` were already pinned
  transitive dependencies and are now explicit direct dependencies. Links are saved before Auth.
  Store-install deferred links and hosted universal/app links are not implemented. See the official
  [Flutter deep-link guidance](https://docs.flutter.dev/ui/navigation/deep-linking).
- **Commands:** runtime shared lock → per-actor/command advisory lock → room lock. Creation also
  locks an advisory active-slot key. Canonical full-intent hashing and receipts precede version
  validation. Savepoints discard failed domain mutations while preserving final rejection receipts.
  State, revision, receipt and room outbox are committed together. Infrastructure failures preserve
  no receipt and can retry the original ID. Flutter persists one pending intent before sending,
  disables conflicting actions, and offers the same-ID retry after an uncertain reply, including
  across reload. Mismatched ACKs unlock retry without losing that saved intent.
- **Room delivery:** the outbox is a durable dirty marker plus audit snapshot in Phase 2. Its
  dispatcher coalesces queued room revisions to the current complete, validated public snapshot.
  It reads committed canonical data, rechecks recipients and emits before committing delivery
  metadata. A delivery-marker rollback can duplicate a committed snapshot; clients ignore older
  revisions. It never broadcasts an uncommitted room mutation. Phase 5 must implement ordered,
  recipient-specific game deltas from committed payloads; room coalescing is not that algorithm.
- **Consistency/presence:** a 15-second subscription includes the installed room revision. Unchanged
  authorized subscriptions emit no redundant membership or snapshot; Phase 3 adds a presence update only to the requester to repair its view without a room broadcast (Claude R1). A new socket always
  receives a full snapshot and membership. Presence is ephemeral authenticated sockets, not
  `players.last_seen_at`. `runtime_heartbeat_at` and durable gameplay clock recovery remain explicit
  Phase 6 work; lobby readiness is not evidence of those features.
- **Scheduling:** maintenance stops when no member sockets are subscribed. Boot/create/join/read
  paths evaluate expiry. With members present, maintenance normally runs once per minute, or once
  per second while timing a host absence. Failed outbox delivery retries during those active ticks
  or next boot. Host transfer waits ten seconds without any host sockets; lowest connected seat
  wins. Voluntary leave transfers immediately, falling back to the lowest occupied seat if all
  peers are offline, preserving the database's host reference until someone returns.
- **Replacement:** a lost runtime epoch retires the old coordinator, emits `server.restarting`,
  disconnects all its authenticated sockets, and makes readiness fail. Flutter reconnects without
  replacing identity and retains any pending intent. This is locally tested; routing during a real
  Render process replacement remains a deployment acceptance item.
- **Rate limits:** general commands are per verified identity; invitation attempts also use a peer
  address bucket. `TRUSTED_PROXY_HOPS=0` ignores spoofable forwarding headers by default. Explicit
  bounded hop configuration selects an address from the right side of `X-Forwarded-For` only after
  the operator verifies the trusted ingress chain. Tests cover spoofed and malformed headers.
  Render's actual forwarding behavior is not yet verified; configure it in Phase 7.
- **Retention:** `npm run local:retention` previews operator-only 30-day cleanup; add `-- --apply`
  to compact eligible receipt bodies and remove terminal room/game/outbox data. Ongoing rooms are
  preserved. Actor/command/hash/status tombstones remain indefinitely so old retries cannot create
  another room (`RECEIPT_EXPIRED`). This bounds large retained bodies, not the number of compact
  tombstones; monitor storage and revisit admission/retention policy if scale grows. Test teardown
  deletes receipts by its synthetic actor keys as well as room IDs. Auth-user cleanup is separate.

The canonical pause reasons remain `MANUAL`, `DISCONNECTED`, `RECOVERY`, `DATABASE_UNAVAILABLE`;
PLAN.md now matches the already shipped schema. The test runner is Node's built-in runner, not Vitest.

## Phase 3 engine contract refinements

Canonical server state now retains `turnOrder` after snake setup finishes and keeps an owner on each internal played development card. Public state requires `winnerVictoryPointCardIds`: empty during play, winner-held VP IDs on completion. Final scores include hidden totals only at completion. The snapshot fixtures include real generated boards and a completed game and pass both Ajv and Dart validation. Schema/protocol remain v1 because gameplay snapshots have never been deployed or persisted; no database migration is needed for these JSON contracts. Rebuild clients with the synchronized assets.

`applyCommand` checks membership, room, expected version, phase, actor obligations and rules before returning a cloned successor. It does not provide command receipts, database locks or broadcasting; Phase 5 must retain those transaction guarantees and persist state, effects, private entropy and receipts atomically. Recorded entropy and the deck are server-only. `projectEffects` filters draw and transfer details by recipient, and its result is an internal projection helper, not yet a `game.delta` wire payload. The room snapshot coalescer must not be reused for ordered game deltas.

## Phase 5 — durable gameplay

`START_GAME` now initializes the real engine under the room lock. Timed starts are explicitly unavailable until the Phase 6 scheduler exists. `CREATE_REMATCH` creates a new lobby only for the finished room's host and respects the single active slot.

`Games.command` follows runtime fence → actor/command advisory lock → existing receipt → room lock → verified membership → game lock → engine. State, sequence log, game outbox and receipt commit atomically. Rejected domain moves leave state unchanged and retain a sanitized receipt. Infrastructure failures retain no false rejection receipt; retry the original ID. Successful initialization records the initial canonical snapshot and random draw context; later logs retain the command and explicit time/entropy for replay. These logs remain server-only.

The game outbox preserves every committed version. It stores a common public delta and private patches keyed by recipient player ID. Delivery combines only the verified recipient's patch. Snapshot subscriptions and outbox delivery share a per-room process queue; database locks serialize writers. Initial/reconnect snapshots can subsume older outbox versions. Delivery markers are advisory: clients ignore duplicate versions, request a snapshot for gaps, and probe the committed version every 15 seconds and on foreground recovery.

Public/private patches are generated only after field-allowlisted projection. Arrays are replaced atomically. Dart validates paths, exact next version, room and owner, then validates the complete reconstructed snapshot before exposing either partition. Hidden hands never enter public patches or activity. `GET /api/v1/rooms/:id/activity` requires the same verified bearer identity and room membership, returns at most 50 log entries, and paginates backward using an exclusive sequence cursor. Only `public_activity` is returned, never raw payloads/effects/entropy.

The Phase 3 addition `winnerVictoryPointCardIds` finalized the predeployment v1 snapshot shape. Phase 5 fixes its missing public-patch allowlist entry before live v1 delivery. Future required shape changes must increment the protocol/state schema version or ship an explicit compatible migration; they must not silently alter active v1 games.

A pending game envelope is persisted before sending. Native uses secure storage; Web uses tab-local sessionStorage, keyed by subject/room/player. Reload waits for the authorized snapshot before replaying the original ID. Transient failures have four delays (1, 2, 4, 8 seconds), then the client exposes manual retry. Acknowledgement does not invent local state or advance its version. Changing identity clears the view and that session's pending intent. No offline move queue or cached private snapshot is created.
